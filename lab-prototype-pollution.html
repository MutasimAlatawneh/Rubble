Prototype Pollution

One sneaky JSON key turns every object in the app into an admin.

1 What it is

In JavaScript, almost every object inherits from one shared parent called Object.prototype. Prototype pollution happens when attacker-controlled input, usually JSON, writes a property onto that shared parent, so every object in the app suddenly “has” it. It belongs to OWASP Top 10:2021 A08 – Software and Data Integrity Failures and is tracked as CWE-1321.

4 Why it matters

Real code is full of checks like if (user.isAdmin) or options like options.shell. If an attacker can plant those on Object.prototype, they can bypass access checks, change how the app behaves, crash it, or, when a polluted option reaches something that runs commands, execute code on the server.

Real incident: in 2019, a prototype pollution bug in Kibana’s Timelion feature (CVE-2019-7609) let attackers run commands on the server. The same year, lodash, one of npm’s most-downloaded libraries, patched the same kind of flaw in defaultsDeep (CVE-2019-10744).

5 The fix

Skip the three keys that lead into a prototype. Everything else is identical, so normal settings still merge.

✅ __proto__, constructor and prototype are never followed, so the merge can only ever touch the object you gave it.

Other solid options: create objects with Object.create(null) (no prototype at all), use a Map, or validate JSON against a strict schema.
