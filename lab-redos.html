ReDoS

A tiny string makes an innocent-looking regex freeze the whole page.

1 What it is

JavaScript’s regex engine matches text by trying options and backing up (“backtracking”) when one fails. Some patterns give it an exponential number of options, so a short, crafted string can keep it busy for seconds, and because JavaScript runs on one thread, the whole page or server freezes. This is ReDoS, part of OWASP Top 10:2021 A04 – Insecure Design, tracked as CWE-1333.

2 The line

An ordinary signup validator:

👉([a-z0-9]+)+ means “groups of letters, repeated”. A run of 25 a’s can be split into groups in millions of ways, and when a final ! makes the match fail, the engine tries every single split before giving up.

4 Why it matters

Every extra character roughly doubles the work. A string only a few characters longer than the ones here would freeze the tab for minutes. On a Node.js server, one such request blocks every user, so a handful of requests can take a service offline without a botnet.

Real incident: on 2 July 2019, one badly written regex in a new Cloudflare firewall rule maxed out CPUs on its machines worldwide and caused a global outage of about 27 minutes. In 2016, Stack Overflow went down for 34 minutes because of a regex that trimmed whitespace.

5 The fix

Remove the nested quantifier. The new pattern accepts exactly the same usernames, but there is only one way to match each character, so time grows in a straight line.

✅One +, no nesting: the engine walks the string once and fails fast at the !.

Extra layers: cap input length before validating, and for untrusted patterns use a linear-time engine such as RE2.
